# Отчёт: коммит 9 — dev-режим с бесконечными деньгами

Коммит: «Dev mode: infinite money» (ветка `stage-2a`).

## Скилы (реально прочитанные в этом сеансе)

- Новых скилов для этой задачи не читалось (маленькая фичa в существующем three.js/DOM-коде, без pivota — правило router). В рамках сеанса уже прочитаны: **router**, **create-game-assets**, **threejs-materials-lighting**. Из применённого: create-game-assets — проверка фичи в живой сцене (три браузерных проверки ниже), а не «по воображению».

## Что сделано

- **`src/core/devmode.ts` (новый)** — чистая функция `devModeEnabled(params, env)`: `params.has('dev') && (env.DEV === true || env.VITE_DEV_TOOLS === '1')`. На `npm run dev` включается параметром `?dev`; production-сборка выключена, если не собрана с `VITE_DEV_TOOLS=1` (сборка CrazyGames делается без переменной).
- **`src/core/save.ts`** — `KEY` стал переменной слота + `setSaveKey(k)`: dev-режим пишет в `niggame.save.dev`, обычная игра — в `niggame.save.v1`; `?reset` очищает только слот текущего режима.
- **`src/main.ts`** — гейт читается до `clearSave()`/`loadSave()` (слот переключается до первого обращения к сейву); в `frame()` каждой кадр **до** `game.update` и любой обработки покупок: `if (devMode) game.money = 1_000_000_000;` — покупки в магазине, дереве, стройке и ленты не падают по деньгам; `stats.earned/sold` не трогаются; `hud.setDev(devMode)`; в `__game` добавлен `dev: boolean`.
- **HUD** — маленькая жёлтая uppercase-метка «DEV» в правом верхнем углу (`#hud-dev` в `index.html`, стиль в `style.css` рядом с существующими правилами HUD, метод `Hud.setDev`). Других изменений UI нет.
- **Когда выключено** — нулевое изменение поведения: тот же ключ сейва, метка скрыта, логика денег не тронута.

## Тесты (`src/core/devmode.test.ts`, 2 новых)

- Таблица истинности: (?dev, DEV=true) → true; (без ?dev, DEV=true) → false; (?dev, DEV=false) → false; (?dev, DEV=false, VITE_DEV_TOOLS='1') → true; (без ?dev, VITE_DEV_TOOLS='1') → false.
- Слот сейва (mock localStorage): dev-режим пишет `niggame.save.dev` (money 1e9 внутри), `niggame.save.v1` остаётся байт-в-байт прежним, `clearSave()` в dev-режиме чистит только dev-слот.

## Браузерные проверки (числа)

1. **`npm run dev`, `/?dev` — включен: PASS.** Метка DEV видна (`hidden: false`, текст «DEV»), `__game.dev === true`. Деньги после первого кадра: **1 000 000 000**. Покупки: ведро (bucket) → true, тачка (wheelbarrow, требует ведро) → true, tree: belt_plans/rake_plans/power → уровни 1/1/1 — после каждой покупки и одного кадра деньги снова **1 000 000 000**. Постройка через build mode: грабли и генератор стоят (`factory.buildings`), лента **5.00 м** (path из 3 точек) — всё прошло проверки денег. `stats.sold = 0` (не тронут). Обычный сейв не тронут: `niggame.save.v1` — 5153.28, байты до/после идентичны; dev-прогресс в `niggame.save.dev` (money 1e9).
2. **`/` без `?dev` — обычный режим: PASS.** Метка скрыта, `dev === false`, деньги из обычного сейва **5153.28** (не 1e9), свои постройки (4) и продажи (832) на месте.
3. **`npm run build && npm run preview` (:4173), `/?dev` — выключен: PASS.** Метка скрыта, `dev === false`, деньги **0** (не 1e9) — production-сборка без `VITE_DEV_TOOLS` дев-режим не включает.

Примечание по методу (не дефект игры): первый заход в проверку №1 я вёл через `buildMode.choose('belt')` напрямую — призрак создаётся в `buildScreen.onPick`, поэтому кадр падал на `ghosts.get('belt')` (моя ошибка управления, не кода). После жёсткой перезагрузки страницы цифры выше сняты начисто.
