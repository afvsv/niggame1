## Дефекты и фиксы

1. **Грабли продолжали работать без питания** — `power` граблей присваивался только внутри цикла генераторов и «залипал» после сноса генератора/выхода из радиуса. Фикс: в начале `tick()` power = 0 у всех граблей; поднимается только расчётом покрытия.
2. **Несколько генераторов перезаписывали power друг друга** (последний выигрывал, спрос не делился, все жгли топливо). Фикс: сетевая модель — `supply` машины = Σ выработки генераторов в радиусе; **троттлинг по всей сети**: `power = min(1, Σвыработка / Σспрос запитанных граблей)` (перекрытие радиусов не задваивает спрос); draw грабли распределяется по её источникам пропорционально ёмкости; burn генератора = `0.83 × draw / 6 кВт × dt`; пустой (fuel ≤ 0) генератор не горит и не мешает живому.
3. **Груз ленты терялся при сейве**: `endPending` не сохранялся; `insert` не ограничивал `n > wadMaxStrands`; `load` отбрасывал `n > wadMaxStrands` и `s ≥ length`. Фикс: `insert(n > wadMaxStrands) → false` (вызывающий сам режет на кучки по зазорам — остаток остаётся у игрока); `Conveyor.serialize()` → `{ wads, pending }`; `load()` принимает объект (и старый массив), `s` в `[0, length]` клампится к `length − 0.01`, `pending` в `[0, wadMaxStrands]`, `jammed = pending ≥ wadMaxStrands`; `BuildingSave.pending?: number`.
4. **Кап топлива на load игнорировал «Большую топку»** — клампился к базовым 100. Фикс: `Factory` принимает `fuelCapOf: () => number` (main.ts передаст `() => d.fuelCap` в К3); тот же кап ограничит ручную заправку.

## Тесты (сначала красные → потом зелёные)
